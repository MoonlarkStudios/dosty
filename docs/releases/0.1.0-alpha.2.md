# Dosty 0.1.0-alpha.2

This alpha adds projects, faster document navigation, and draft recovery for
connected blogs.

## What's new

- Open and resume projects from Welcome. Quick Open finds files, pinned
  documents, and headings. Find in Folder searches Markdown across a project,
  and backlinks show which files link to the current document.
- Write mode gains updated typography and section folding. Tables support inline
  cell editing and spreadsheet clipboard transfers. Task checkboxes are
  interactive, and Live supports strikethrough and footnote authoring.
- Connect to a hosted workspace to edit, preview, and publish blog drafts.
  If a newer revision was saved elsewhere, Dosty keeps the local Markdown and
  post details. Restore them after restart and use **Save as new draft** when
  the workspace supports it. **Save As…** writes a local Markdown copy while
  keeping the hosted draft open. [Recovery workflow](https://github.com/MoonlarkStudios/dosty/blob/main/docs/writing-workflows.md#recovery-and-export)

## Downloads and installation

- **macOS** users can choose the Apple silicon `arm64.dmg` or Intel
  `x86_64.dmg`. Drag Dosty into Applications. The builds target macOS 12 or
  later and are ad-hoc signed. [Opening the app](https://support.apple.com/en-us/102445)
- **Windows** users can run the x86_64 setup EXE. It installs per user and
  requires no administrator privileges. The installer and app are unsigned, so
  SmartScreen may warn or block installation. [SmartScreen](https://learn.microsoft.com/en-us/windows/apps/package-deploy/smartscreen-reputation)
- Install the **Debian/Ubuntu** amd64 DEB with
  `sudo apt install ./dosty_*.deb`. The initial validation targets are
  Ubuntu 24.04 or later and Debian 13.
- Install the **Fedora** x86_64 RPM with `sudo dnf install ./dosty-*.rpm`.
  The initial validation target is Fedora 43 or later.

Linux file dialogs need a working desktop session and portal backend. Verify
downloaded packages against `SHA256SUMS`. Matching source is included.

## Hosted draft recovery smoke test

Run this on the installed macOS, Windows, and Linux builds with an isolated
`DOSTY_CONFIG_DIR`. Use a test workspace with draft creation enabled, a
disposable post, and distinct desktop and browser edit markers.

1. Save a test post with a cover. Open the same saved revision in Dosty and
   the browser editor.
2. In Dosty, edit the Markdown and cover alt text, leaving both unsaved. In the
   browser, make a different Markdown edit and save it to the original post.
3. Save in Dosty and confirm it reports a revision conflict and keeps the
   desktop edits. Close the window and choose **Keep recovery copies**.
4. Relaunch with the same configuration directory. Open **Recovery Copies…**
   from Help on macOS or **File → Help & settings…** on Windows and Linux.
   Open the test copy and verify the desktop Markdown and cover alt text.
5. Reconnect to the workspace, retry **Save**, and confirm the conflict still
   appears. Choose **Save as new draft**.
6. Open both posts in the browser. Confirm the new draft has the desktop
   Markdown and cover alt text, and the original still has the browser edit.

Packaged-build validation is pending. Record the OS version, architecture,
package filename, and outcome for each run before publication.

## Known limitations

Screen-reader support is incomplete. CJK input, bidirectional editing, and
Windows and Linux desktop workflows need broader native validation.
Recovery can lose edits made since the most recent checkpoint.
[Release readiness](https://github.com/MoonlarkStudios/dosty/blob/main/docs/evaluation.md#remaining-release-work)
